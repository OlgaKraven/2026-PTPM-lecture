# Разработка

Установка: `npm ci`. Разработка: `npm run dev`. Сборка: `npm run build`. Проверка содержания: `npm run validate`.

Учебные примеры: `python -m unittest discover -v` и `python mutation_demo.py` в каталоге `examples`.

После изменения примеров обновить скачиваемый архив командой `python scripts/package-examples.py`. Команда `python scripts/package-examples.py --check` проверяет точное совпадение архива с исходными файлами; она включена в CI.

Исходные темы находятся в `authoring`. Сборка формирует `public/course.json`, пакет заметок `public/teaching/notes.json`, ключи `public/assessment.json` и самостоятельные случаи `public/question-supplements.json`. Связные MD преподавателя и карта соответствия формируются локально в игнорируемом `private/teacher`; хранение преподавательских текстов — в BrainM. В публичную сборку входят только необходимые JSON.

Структура и взаимодействия сверены с `OlgaKraven/2026-OKFKS-lecture`, commit `e36d019`. Для ПТПМ сохранены три предметных вопроса в каждой лекции и часы РПД. На каждый вопрос приходятся объяснение, разобранный и изменённый случаи, типичная ошибка, вывод, самостоятельная задача и четыре вида самопроверки.

`src/infographics`, `src/lab`, `src/presentation` используют компоненты текущего ОКФКС. Данные дисциплины и 24 предметные модели ПТПМ находятся отдельно, в `authoring/diagrams.mjs`, `authoring/subject-visuals.mjs` и `src/infographics/data/ptpm.json`. Видимые пошаговые объяснения перед моделями — в `authoring/student-explanations.mjs`.

Отчёты проверок и карта программы находятся в `docs`; они не показываются в учебном каталоге и на слайдах.

Публикация: `.github/workflows/check.yml` собирает и проверяет проект, затем размещает `dist` на GitHub Pages. Развёртывание выполняется только из `main` после успешных проверок; pull request проходит проверки без публикации. Повторный запуск доступен через Actions → «Проверка и публикация лекций» → Run workflow. Адрес: https://olgakraven.github.io/2026-PTPM-lecture/. Содержимое, JSON преподавателя и примеры публикуются из одной сборки. Для проверки выпуска сверяют SHA задания, опубликованные JSON и файлы JS/CSS с локальной сборкой, затем проверяют интерфейс по публичному адресу.

При проверке самостоятельной понятности сначала читать только общедоступные слайды и разборы, затем отдельно текст преподавателя. Для каждого вопроса сверять исходные условия, первый шаг, получение результата и границы вывода. Смена тарифа должна явно ограничиваться своим вариантом; сокращённый фрагмент кода не подтверждает свойства полной версии без видимого пояснения. Пример зависимости тестов от порядка проверять различающим запросом: reserve(5) различает stock=6 и stock=4, reserve(7) — нет. Контроль ID и текста панели дополняет эту предметную проверку, но не заменяет её.
