<a id="s05-02-dependencies-s004"></a>

### 4. Зависимость влияет на повторяемость

Если функция сама читает сеть, часы или базу данных, результат зависит от внешнего состояния. Можно выделить вычисление и отдельно проверить адаптер внешнего источника. Реальный запрос полезен в интеграционном тесте, но затрудняет изолированную проверку расчёта.

Представим сумму заказа в рублях: количество евро умножается на курс. Если тест каждый раз обращается к живому курсу, ожидаемое число меняется, а отказ сети выглядит как дефект расчёта. Не делаем вывод, что такой модуль вообще невозможно тестировать. Меняем границу: отдельно известный курс и арифметика, отдельно получение курса и формат ответа.

**Запишите.** Зависимость модуля — используемый им внешний объект, источник данных или сервис, влияющий на выполнение.

<a id="s05-02-dependencies-s005"></a>

### 5. Какие условия контролируются

Реальные соединения проверяют отдельно на границе интеграции.

| Зависимость | Риск теста | Вариант контроля |
| --- | --- | --- |
| Живой курс валюты | Меняется число | Передать известный курс |
| Системное время | Порог наступает в разный момент | Передать известное время |
| Файл на диске | Состояние зависит от устройства | Подготовить временный файл |
| Сеть | Отказ и задержка не управляются | Подменить источник в модульном тесте |

Каждая строка задаёт свой вид контроля. Заглушка не универсальное решение всему: для файловой логики уместен временный каталог, а для арифметики — обычное число. Главное — знать, какие условия воспроизводятся и что именно проверено. Изоляция полезна для диагностики, но интеграционные риски остаются и требуют отдельного набора.

<a id="s05-02-dependencies-s006"></a>

### 6. Разделение ответственности

1. **Источник.** get_rate("EUR") возвращает курс
2. **Модуль.** Стоимость = евро × курс
3. **Модульный тест.** Известный ответ источника и точная сумма
4. **Интеграционный тест.** Реальный формат, соединение и обработка ответа

Четыре блока здесь показывают границы ответственности, а не обязательное выполнение модульного теста перед интеграционным. Нам нужно различать причины расхождений. Если курс 100 и сумма 20, ожидаем 2000 независимо от сети. Если адаптер не может прочитать JSON реального провайдера, проблема проявится на другой границе. Не обещаем работоспособность соединения по тесту с известным числом.

### 10. Внешний источник передаётся параметром

```python
def order_total(euros, rate_source):
    rate = rate_source("EUR")
    return euros * rate
```

Учебный контракт: euros — целое ≥0; источник возвращает положительный целый курс рублей за евро.

Это минимальный фрагмент механизма. Полная версия учебного файла дополнительно проверяет вход и ответ источника. Функция не знает, пришёл курс из сети или из теста: ей нужен вызываемый объект с одним аргументом. Мы передаём сам источник, а не уже выполненный вызов. Такое выделение зависимости не требует сложного контейнера или специальной библиотеки.

<a id="s05-02-dependencies-s011"></a>

### 11. Заглушка возвращает известный ответ

```python
def fixed_rate(currency):
    if currency != "EUR":
        raise ValueError("unsupported currency")
    return 100

actual = order_total(20, fixed_rate)
# actual == 2000
```

Источник не обращается к сети. Он также отклоняет неожиданный аргумент.

Вызов order_total передаёт строку EUR, получает сто и умножает на двадцать. Ограничение аргумента полезно: слишком покладистая заглушка, которая возвращает сто на любой запрос, пропустит ошибку валюты USD вместо EUR. Здесь задан небольшой контракт источника. В рабочем проекте он также может включать единицы, округление и обработку отсутствующего курса.

<a id="s05-02-dependencies-s012"></a>

### 12. Заглушка подменяет ответ, а не проверяемый расчёт

В тесте остаётся настоящий order_total; подменяется только источник курса. Если вместо функции расчёта вернуть заранее 2000, тест перестанет проверять умножение. Заглушка должна реализовать достаточную часть интерфейса зависимости.

Убедимся, что мы не обошли предмет теста. Настоящая функция должна получить 100 и сама вычислить 20×100. Если заглушить её целиком, при дефекте умножения результат всё равно будет 2000 и тест ничего не заметит. Для простой зависимости обычная функция читается яснее динамической подмены. Различия stub, mock и fake существуют, но здесь достаточно понять роль управляемого ответа.

**Запишите.** Заглушка — тестовый заменитель зависимости, выдающий заранее определённые ответы для нужных условий проверки.

### 16. Проверка результата на настоящем модуле

```python
def test_order_total_uses_rate(self):
    def source(currency):
        self.assertEqual(currency, "EUR")
        return 100
    self.assertEqual(order_total(20, source), 2000)
```

Один сценарий проверяет запрос EUR и итог 2000 при известном ответе.

Источник проверяет нужный аргумент и возвращает курс. Обратите внимание: это уже тестовый заменитель с наблюдением обращения, а не только пассивная заглушка. Называть его можно по выполняемой роли; важнее понимать проверяемые свойства. Если order_total вообще не вызовет source и вернёт константу 2000, этот единственный пример может пройти. Нужны другие входы или явное наблюдение вызова, если это часть цели.

<a id="s05-02-dependencies-s017"></a>

### 17. Воспроизводимый отказ зависимости

```python
def test_source_failure_is_propagated(self):
    def unavailable(currency):
        raise ConnectionError("offline")
    with self.assertRaises(ConnectionError):
        order_total(20, unavailable)
```

Учебный контракт сохраняет ConnectionError источника и не возвращает выдуманную сумму.

Это управляемый отказ: нам не нужно отключать сеть у всех студентов. Модуль получает конкретное исключение и должен передать его вызывающему коду. Другое приложение может преобразовывать его в собственную ошибку; тогда ожидание задавалось бы иначе. Нельзя объявить нулевую сумму успешным расчётом только потому, что хочется избежать исключения.

<a id="s05-02-dependencies-s018"></a>

### 18. Сила и границы свидетельств

Модульная и интеграционная проверки имеют разные границы.

| Проверка | Подтверждает | Остаётся проверить |
| --- | --- | --- |
| Курс 100, сумма 20 | 2000 при данном ответе | Реальный API и формат |
| Источник выбросил ConnectionError | Передачу отказа по контракту | Реальный тайм-аут |
| Источник возвращает −1 | Валидацию ответа | Какие ответы даёт провайдер |

Успешный модульный тест не означает, что провайдер действительно возвращает целое число в рублях. Возможно, API отдаёт строку или цену за сто единиц валюты. Это важный интеграционный риск. Но он не делает изолированную проверку ненужной: арифметика и обработка отказов остаются воспроизводимыми и быстро диагностируются.
